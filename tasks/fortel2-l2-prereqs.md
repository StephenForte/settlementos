# ForteL2 operator checklist — before SettlementOS F2 deploys to 852

Hand this to the ForteL2 side (the machine running the OP Stack). It lists
everything the L2 operator must do or decide before SettlementOS deploys its
contracts to `fortel2-sepolia` (chain 852). SettlementOS-side work is tracked
separately in `tasks/f2-prep-notes.md`.

## 1. Fund the SettlementOS deployer on L2 — the only funding needed

| Account | Address | Needs on L2 852 |
|---|---|---|
| SOS deployer/operator | `0x5128889F20Ec13e0Be38b2BeBC568594159B652d` | **≥ 0.05 ETH** (0.1 comfortable) |

- Route: L1→L2 deposit through the Sepolia Standard Bridge
  (`deposit-eth-sepolia.sh` patterns; OptimismPortalProxy
  `0xb4679b1c65e5c07bac95988583c2d7a65108c624`), recipient = the SOS deployer
  address above. Any funded L1 account can send it — the SOS deployer also
  holds 0.80 Sepolia L1 ETH of its own if self-depositing is easier (its key
  lives only in the SettlementOS `.env`).
- Sizing: the Base Sepolia deploy cost ~0.002 ETH and SOS dust-funds its role
  wallets with ~0.0018 more, so real need is < 0.005 ETH; 0.05 is 10× headroom
  for re-runs and demos.
- **No other account needs funding.** `SEQUENCER`, `CHALLENGER`, `DEMO_A`,
  `DEMO_B` are ForteL2-side accounts — SettlementOS never uses them. The SOS
  treasury and entity dust wallets are *generated by the deploy script* and
  funded from the deployer's L2 balance, so they cannot be pre-funded.

## 2. RPC reachability — the stack is not on the SOS machine

The F1 default (`http://127.0.0.1:9545`) assumes loopback. With the stack on a
separate machine, pick one:

- **Run the F2 deploy on the L2 machine** (current plan): clone
  `github.com/StephenForte/settlementos` there; loopback works as-is. The SOS
  `.env` (with `DEPLOYER_PRIVATE_KEY`) must be recreated there by hand — it is
  gitignored and must never be committed or sent over anything unencrypted.
- **Or expose the sequencer RPC** to the SOS machine (LAN bind / Tailscale /
  SSH tunnel) and set `FORTEL2_SEPOLIA_RPC_URL=http://<host>:9545` in the SOS
  `.env`. Do not expose 9545 to the public internet.

## 3. Health checks SOS will run first (make sure they pass)

```bash
cast chain-id     --rpc-url http://127.0.0.1:9545   # must return 852
cast block-number --rpc-url http://127.0.0.1:9545   # must advance
cast gas-price    --rpc-url http://127.0.0.1:9545   # informs dust targets
cast balance 0x5128889F20Ec13e0Be38b2BeBC568594159B652d --rpc-url http://127.0.0.1:9545
```

The deploy script hard-fails if the RPC is unreachable, the chain id is not
852, or the deployer balance is below its minimum — nothing falls back.

## 4. Stability window

- Keep the Sepolia deployment **pinned** (no Phase 7 re-genesis/wipe) until
  after SOS has deployed and demoed — a wipe deletes the SOS contracts and
  forces a coordinated redeploy.
- Keep the sequencer up during the deploy and any settlement demo; SOS
  execution is synchronous (a settled payment is a few blocks end-to-end).

## 5. Optional — Render replica read URL

If you want SOS balance/display reads served by the replica instead of the
sequencer, share the Render read RPC URL; SOS sets it as
`FORTEL2_SEPOLIA_READ_RPC_URL` (F1 already routes only balance reads there —
writes and tx confirmation always stay on the sequencer). Purely optional.

### Replica OOM on catch-up (seen 2026-08-05)

A quiet OP Stack chain still emits empty singular batches (`txs=0`) every ~2s.
If the Render replica falls behind and then catches up, op-node can decode a
huge backlog in one burst (`decoded singular batch from channel` floods, then
`Advancing bq origin` with `originBehind=true`) and OOM a small instance.

- Bump Render RAM (≥2GB is a safer floor for op-node + execution client) or
  wipe/resync from a packed snapshot instead of deriving a long empty backlog
  live.
- Turn log level down to `warn` during catch-up so batch-decode spam does not
  add I/O pressure.
- SOS writes are unaffected (sequencer RPC). If the replica is flaky, unset
  `FORTEL2_SEPOLIA_READ_RPC_URL` so balance/display reads hit the sequencer.

## 6. Bookkeeping

- If the sequencer host/exposure story changed (no longer "loopback on the
  Mac"), update `deployments/rail-interface.json` accordingly so it stays the
  canonical source.

## Explicitly NOT needed from ForteL2

- No genesis predeploys and no contracts deployed on the L2 side — SOS deploys
  its own `MockERC20`s + `PaymentSettlement` + `TokenizedMMF`.
- No fee/gas parameter changes, no paymaster, no canonical USDC.
- No funding of SOS treasury/entity wallets (script-generated, deployer-funded).
