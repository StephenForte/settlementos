## Codebase Patterns
- Read AGENTS.md first — it is the engineering guide (architecture map, invariants,
  gotchas) and CLAUDE.md just points at it. Add durable learnings there, not to a new
  CLAUDE.md.
- Quality gate for every commit: `npm test` (self-contained: compiles contracts, boots
  Hardhat on ports 9545/9546, builds a fresh SQLite fixture under tests/.tmp — never
  touches dev chains or the dev DB), then `npx tsc --noEmit`, then `npm run lint`.
- Run `npm run compile` after ANY contract change — tests read artifacts from
  `chain/artifacts/` (gitignored) and will use stale bytecode otherwise.
- Contract tests: `tests/integration/*.test.ts`, driven with viem via
  `helpers/deploy.ts` (`clientsFor(rpc, chainId)` + `artifact(name)`), fixture accounts
  from `tests/fixture.ts` ACCOUNTS. Assert reverts with
  `await expect(...).rejects.toThrow(/require message/)`.
- A test can deploy its own contract instance against the fixture chain (see the rogue
  token in contract.test.ts) — no need to wire something into global-setup just to test it.
- Addresses read from a contract are EIP-55 checksummed; deployments.json stores them
  lowercase. Lowercase both sides before comparing.
- Money: fiat = decimal strings, on-chain = bigint base units. Never a JS float on-chain.
- Solidity contracts follow one house style: `admin` + `operators` mapping,
  `onlyAdmin`/`onlyOperator` modifiers, constructor makes the deployer both, short
  lowercase revert strings ("not operator").
- No Prisma migrations directory: the schema is applied with `prisma db push`.
  `npm run setup` runs `prisma generate && prisma db push` before seeding, so after
  editing prisma/schema.prisma that is the command that syncs the dev DB + client.
  The test fixture pushes the schema itself in tests/global-setup.ts, so `npm test`
  picks up schema changes with no extra step.
- Demo entities are seeded in TWO places that must stay in sync: `scripts/setup.mjs`
  (dev DB) and `ENTITIES` in `tests/helpers/deploy.ts` (test fixture). Adding an
  Entity field means editing both.
- `npm run setup` needs BOTH local chains up (8545 + 8546) or it exits. To verify it
  without destroying the user's dev state: back up `chain/deployments.json` and
  `prisma/dev.db`, start the chains, run setup, then kill the chains and restore.
- Contract deploys are wired in TWO places that must stay in sync: `setupChain()` in
  `scripts/setup.mjs` (dev chains) and `deployChain()` in `tests/helpers/deploy.ts`
  (test fixture). Anything a new contract needs to be usable — token approvals,
  minted balances — belongs in both, and its address goes in the returned
  `contracts` object so it lands in deployments.json.
- `lib/chain.ts` ABI exports are `as const`, so viem narrows `functionName` to a
  literal union. A test helper taking `functionName: string` will NOT typecheck
  against them — type the param as the union (or cast the ABI to `Abi`).
- Optional per-network contracts resolve through a lookup that returns `undefined`
  instead of throwing (`mmfAddress`), because live testnets legitimately lack them.
  Follow that shape for anything deployed only on some networks.
- The dev server may find :3000 taken and fall back to :3001 — read the actual port
  out of the dev log before curling it.
- `audit()` JSON-stringifies its detail, and JSON.stringify THROWS on a bigint. Convert
  base units to strings before auditing them.
- viem writes return a receipt, not the contract function's return value. Read the
  relevant view before/after (or decode the event) to capture what a mutator returned.
- Contract writes go through the operator helpers in lib/chain: `operatorWrite()` for
  PaymentSettlement, `mmfOperatorWrite()` for TokenizedMMF. Don't hand-roll a wallet.
- Tests that move fixture funds (parking, minting, accruing) must unwind at the end —
  the chains, the DB, and the MMF are shared across test files, which run sequentially.
- lib/treasury throws only `TreasuryError` with a typed `code` — add a code to the
  `TreasuryErrorCode` union rather than throwing a bare Error, so US-007's routes can
  map cause -> HTTP status in one place. Tests assert with
  `.rejects.toMatchObject({ code: "..." })`.
- Rows that model financial history (TreasuryPosition, AuditEvent) are append-only:
  update status in place (ACTIVE -> RECALLED), never delete. Derive current value
  (shares x live index) instead of storing a mutable balance.
- MMF accrual is IRREVERSIBLE (the contract's index is monotonic). Any suite that
  accrues the shared fixture fund leaves it above par forever, so tests must assert
  invariants (index >= par, shares = value/index, round-trip >= principal) rather than
  par-equality, and a test file that accrues should do it in its LAST block. Vitest
  file order is sequential but NOT alphabetical, so never rely on "my file runs last":
  derive expected amounts from the LIVE index (`valueOfShares(shares, index)` is exactly
  what `redeem` pays), not from par.
- API routes: `route.ts` is the only routable filename, so shared glue colocates fine
  under `app/api/**` (e.g. `app/api/treasury/errors.ts` maps `TreasuryErrorCode` ->
  HTTP status in one place). Keep HTTP concerns out of lib/; keep handlers thin.
- Route tests import the handler directly (`import { POST } from "@/app/api/.../route"`)
  and call it with a `NextRequest` — no HTTP server. A constructed Request with a body
  needs the `{ duplex: "half" }` cast (undici).
- Module import direction inside lib/ is executor → routing → treasury → chain/db.
  Adding an import that points back up the chain (treasury → routing) cycles the graph.
  If two modules need the same fact, put it in the LOWER one and have the higher import
  it (e.g. `parkedBalance` lives in treasury; routing calls it).
- Anything frozen into `Payment.quoteJson` at quote time (route id, fees, and now
  `recall_required`) is a SNAPSHOT — the chain and the DB can move before execution.
  Treat those fields as a hint, and keep the executor's own re-checks. Corollary: a
  helper the executor calls off such a flag should be a safe no-op when the condition
  no longer holds.
- The MMF is backed by mockUSDC only, and the executor reserves the DESTINATION asset.
  So a payment can only exercise MMF liquidity when its destination currency is USD
  (USD→USD is a legal corridor — `midRate` returns 1 when source == dest). A USD→JPY
  payment reserves mockJPY and never touches the fund.

## 2026-07-14 08:25 - US-006 (Simulated daily yield accrual)
- `lib/treasury.ts`: `accrueDaily(networkId, annualRateBps = MMF_ANNUAL_RATE_BPS)` reads the
  fund's live index, computes one day of yield, advances the contract via
  `mmfOperatorWrite(networkId, "accrue", [newIndex])`, and audits `TREASURY_ACCRUED`
  (network, fund, old index, new index, rate in bps, days, tx hash). Rate is a constant —
  `MMF_ANNUAL_RATE_BPS = 350n` (3.5% APY) — overridable per call.
- Pure math, exported and unit-tested so it is deterministic and chain-free:
  `dailyIndex(index, bps) = index + (index * bps) / (10_000n * 365n)` (bigint, floor) and
  `valueOfShares(shares, index) = shares * index / 1e18`. Floor division means the index
  can only rise or stay put, which is exactly what the contract's monotonic `accrue`
  requires. Also `currentIndexOf(networkId)` for the API/UI stories.
- A position's value stays DERIVED: accrual writes nothing to TreasuryPosition — the row
  keeps only `shares` + `indexAtEntry`, and value = shares x live index.
- New `TreasuryErrorCode` `INVALID_RATE` (negative bps); `fundFor(networkId)` factored out
  of `fundAssetFor` so accrual can resolve the fund without naming an asset (NO_FUND).
- Tests: `tests/unit/treasury.test.ts` (new, 6 tests — par + 3.5% APY gives exactly
  1000095890410958904, rate scaling, compounding, dust index cannot decrease, negative rate
  throws) and 2 in `tests/db/treasury.test.ts` (on-chain park 100k -> accrueDaily -> recall
  returns principal + ~9.589 mockUSDC of yield paid out of the fund's buffer, position row
  untouched, TREASURY_ACCRUED on an INTACT audit chain; accrue on base-sepolia -> NO_FUND).
- `tests/integration/mmf.test.ts`: the fixture-fund wiring assertions were par-equality
  (`currentIndex == 1e18`, `yieldBuffer == MMF_YIELD_BUFFER`, `shares == PARK`). Once the db
  suite accrues that fund those are false and file order is not guaranteed, so they now
  assert invariants: index >= par, 0 < buffer <= MMF_YIELD_BUFFER, totalShares == 0, balance
  == buffer, shares == PARK * 1e18 / index, and a round-trip within 1 base unit of dust.
- Files changed: lib/treasury.ts, tests/unit/treasury.test.ts (new), tests/db/treasury.test.ts,
  tests/integration/mmf.test.ts, AGENTS.md (architecture-map row + "accrual is one-way" gotcha).

  - **Accrual is irreversible and the fixture fund is shared.** Put anything that accrues in

    index) then asset = floor(shares * index / 1e18) can lose a base unit. Assert `>=` principal
    (or a 1-unit dust band), never `==`.
  - US-007 (routes) can now map the full typed-error set: NO_FUND, UNSUPPORTED_ASSET,
    INVALID_AMOUNT, INVALID_RATE, INSUFFICIENT_FREE_BALANCE, NOT_ELIGIBLE, POSITION_NOT_FOUND,
    POSITION_NOT_ACTIVE. `currentIndexOf()` + `valueOfShares()` are what GET /api/treasury/positions
    should use for "current value per position" (one index read per network, not per row).

## 2026-07-14 08:32 - US-007 (Treasury API routes: park, recall, positions, accrue)
- Four route handlers under `app/api/treasury/`, all snake_case in and out, all thin
  (validate the body, delegate to lib/treasury, map the typed error):
  - `POST park` { network, asset, amount, entity_id } -> { position_id, status, tx_hash,
    shares, index_at_entry }. entity_id is REQUIRED here (the lib arg is optional) so the
    institutional-only guardrail is always enforced server-side.
  - `POST recall` { position_id } -> { position_id, status, tx_hash, shares, amount,
    index_at_exit }.
  - `GET positions` -> positions newest-first with a DERIVED current_value / accrued_yield
    (shares x the fund's live index). One index read per network, not per row; a RECALLED
    row reports null for the live fields.
  - `POST accrue` { network } -> { network, old_index, new_index, annual_rate_bps, tx_hash }.
- `app/api/treasury/errors.ts`: the single TreasuryErrorCode -> HTTP status table —
  NOT_ELIGIBLE 403, POSITION_NOT_FOUND 404, INSUFFICIENT_FREE_BALANCE + POSITION_NOT_ACTIVE
  409, NO_FUND / UNSUPPORTED_ASSET / INVALID_AMOUNT / INVALID_RATE 400, anything else 500.
  Response shape is `{ error, code }`, so `{ error }` still matches the other routes.

## 2026-07-14 08:40 - US-008 (Route engine treats parked liquidity as available-with-recall-delay)
- `lib/treasury.ts`: two additions on top of park/recall/accrue.
  - `parkedBalance(networkId, symbol)` — derived value of every ACTIVE position on that
    network (sum of `shares x live index`), in base units. Returns `0n` (never throws)
    where no fund is deployed, so quoting can call it on any network including the real
    testnets.
  - `recallForPayment({ networkId, asset, amount, paymentId })` — frees `amount` for a
    payment by recalling parked positions oldest-first (FIFO: the oldest has accrued
    longest). No-op when the free balance already covers the amount. Pre-checks
    `parkedBalance >= shortfall` so it never half-recalls into a doomed payment, and
    still re-checks after the loop (floor-division dust / a row-vs-fund disagreement).
    Audits a payment-linked `TREASURY_AUTO_RECALLED` (needed, free before, shortfall,
    amount recalled, position ids, tx hashes) on top of the per-position
    `TREASURY_RECALLED` events that `recall()` already writes.
- `lib/routing.ts`: `liquidityOk` (boolean) became `liquidityCheck` returning
  `{ ok, recallRequired }`. Free liquidity short but free + parked covers it → the quote
  is STILL offered, with `recall_required: true`. `RouteOption` gains `recall_required`,
  wired into all four route branches (instant, batched, bridged, source-chain fallback)
  and defaulting to `false` in `common`, so quotes with ample free liquidity are byte-for-
  byte unchanged. Also exports `parkedLiquidity(asset, network)` (the decimal-string view,
  mirroring `availableLiquidity`). The parked lookup only runs in the shortfall branch —
  a normal quote costs no extra queries.

  BEFORE the liquidity reservation and the escrow (reserving first would reserve against a
