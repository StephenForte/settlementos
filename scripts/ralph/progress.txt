## Codebase Patterns
- Read AGENTS.md first — it is the engineering guide (architecture map, invariants,
  gotchas) and CLAUDE.md just points at it. Add durable learnings there, not to a new
  CLAUDE.md.
- Quality gate for every commit: `npm test` (self-contained: compiles contracts, boots
  Hardhat on ports 9545/9546, builds a fresh SQLite fixture under tests/.tmp — never
  touches dev chains or the dev DB), then `npx tsc --noEmit`, then `npm run lint`.
- Run `npm run compile` after ANY contract change — tests read artifacts from
  `chain/artifacts/` (gitignored) and will use stale bytecode otherwise.
- Contract tests: `tests/integration/*.test.ts`, driven with viem via
  `helpers/deploy.ts` (`clientsFor(rpc, chainId)` + `artifact(name)`), fixture accounts
  from `tests/fixture.ts` ACCOUNTS. Assert reverts with
  `await expect(...).rejects.toThrow(/require message/)`.
- A test can deploy its own contract instance against the fixture chain (see the rogue
  token in contract.test.ts) — no need to wire something into global-setup just to test it.
- Addresses read from a contract are EIP-55 checksummed; deployments.json stores them
  lowercase. Lowercase both sides before comparing.
- Money: fiat = decimal strings, on-chain = bigint base units. Never a JS float on-chain.
- Solidity contracts follow one house style: `admin` + `operators` mapping,
  `onlyAdmin`/`onlyOperator` modifiers, constructor makes the deployer both, short
  lowercase revert strings ("not operator").
- No Prisma migrations directory: the schema is applied with `prisma db push`.
  `npm run setup` runs `prisma generate && prisma db push` before seeding, so after
  editing prisma/schema.prisma that is the command that syncs the dev DB + client.
  The test fixture pushes the schema itself in tests/global-setup.ts, so `npm test`
  picks up schema changes with no extra step.
- Demo entities are seeded in TWO places that must stay in sync: `scripts/setup.mjs`
  (dev DB) and `ENTITIES` in `tests/helpers/deploy.ts` (test fixture). Adding an
  Entity field means editing both.
- `npm run setup` needs BOTH local chains up (8545 + 8546) or it exits. To verify it
  without destroying the user's dev state: back up `chain/deployments.json` and
  `prisma/dev.db`, start the chains, run setup, then kill the chains and restore.
- Contract deploys are wired in TWO places that must stay in sync: `setupChain()` in
  `scripts/setup.mjs` (dev chains) and `deployChain()` in `tests/helpers/deploy.ts`
  (test fixture). Anything a new contract needs to be usable — token approvals,
  minted balances — belongs in both, and its address goes in the returned
  `contracts` object so it lands in deployments.json.
- `lib/chain.ts` ABI exports are `as const`, so viem narrows `functionName` to a
  literal union. A test helper taking `functionName: string` will NOT typecheck
  against them — type the param as the union (or cast the ABI to `Abi`).
- Optional per-network contracts resolve through a lookup that returns `undefined`
  instead of throwing (`mmfAddress`), because live testnets legitimately lack them.
  Follow that shape for anything deployed only on some networks.
- The dev server may find :3000 taken and fall back to :3001 — read the actual port
  out of the dev log before curling it.
- `audit()` JSON-stringifies its detail, and JSON.stringify THROWS on a bigint. Convert
  base units to strings before auditing them.
- viem writes return a receipt, not the contract function's return value. Read the
  relevant view before/after (or decode the event) to capture what a mutator returned.
- Contract writes go through the operator helpers in lib/chain: `operatorWrite()` for
  PaymentSettlement, `mmfOperatorWrite()` for TokenizedMMF. Don't hand-roll a wallet.
- Tests that move fixture funds (parking, minting, accruing) must unwind at the end —
  the chains, the DB, and the MMF are shared across test files, which run sequentially.
- lib/treasury throws only `TreasuryError` with a typed `code` — add a code to the
  `TreasuryErrorCode` union rather than throwing a bare Error, so US-007's routes can
  map cause -> HTTP status in one place. Tests assert with
  `.rejects.toMatchObject({ code: "..." })`.
- Rows that model financial history (TreasuryPosition, AuditEvent) are append-only:
  update status in place (ACTIVE -> RECALLED), never delete. Derive current value
  (shares x live index) instead of storing a mutable balance.

## 2026-07-14 08:15 - US-004 (Park: sweep idle treasury balance into the MMF)
- `lib/treasury.ts` (new): `park({ networkId, asset, amount, entityId? })` resolves the
  network's fund via `mmfAddress`, asserts the fund is actually backed by that asset
  (reads `asset()` and compares lowercased), converts the decimal amount with
  `toBaseUnits` (bigint end to end), ensures the treasury's approval, subscribes as the
  operator, and writes an ACTIVE `TreasuryPosition` with the park tx hash. Minted shares
  come from the treasury's sharesOf delta (a write only yields a receipt, so subscribe's
  return value is not readable). Also exports `freeTreasuryBalance()` and a typed
  `TreasuryError` with codes NO_FUND / UNSUPPORTED_ASSET / INVALID_AMOUNT /
  INSUFFICIENT_FREE_BALANCE / NOT_ELIGIBLE (US-007 maps these to HTTP statuses).
- Guardrails: park refuses when the amount exceeds treasury balance minus RESERVED
  LiquidityReservation rows (all bigint — no float rounding), and the optional
  `entityId` enforces mmfEligible && mmfOptIn at the lib layer, so US-007's API guard
  and US-010's rejection test both have a single source of truth.
- `lib/chain.ts`: `mmfOperatorWrite(networkId, "subscribe"|"redeem"|"accrue", args)`
  (operatorWrite is hard-wired to PaymentSettlement's address/ABI, so the fund needed its
  own operator-signed path), `tokenAllowance()`, `ensureTreasuryAllowance()` (approves MAX
  only when the current allowance is short — parking self-heals if a fund is redeployed
  under an existing DB), plus `allowance` in ERC20_ABI.
- Audit: `TREASURY_PARKED` (exported constant) with network, asset, decimal amount, base
  units, shares, index at entry, fund address, tx hash, and the entity when supplied.
- `tests/db/treasury.test.ts` (new, 3 tests): park records the position and shrinks
  `availableLiquidity` by exactly the parked amount with the asset landing in the fund;
  reserved liquidity cannot be parked but the unreserved remainder still can; bad amount /
  wrong asset / no-fund network raise the right typed codes and create no row.
- Files changed: lib/treasury.ts (new), lib/chain.ts, tests/db/treasury.test.ts (new),
  AGENTS.md (architecture-map row, reserved-liquidity invariant, bigint-audit gotcha).
- Checks: 106 tests pass (was 103), `npx tsc --noEmit` clean, `npm run lint` clean.
- **Learnings for future iterations:**
  - **`audit()` JSON-stringifies its detail and JSON.stringify THROWS on a bigint.**
    Stringify base units (or use `fromBaseUnits`) before putting them in an audit detail.
  - `operatorWrite()` only talks to PaymentSettlement. Use `mmfOperatorWrite()` for the
    fund — US-005 (`redeem`) and US-006 (`accrue`) go through it.
  - viem writes return a receipt, not the function's return value. To capture a value a
    mutator returns (subscribe → shares, redeem → assetAmount), read the relevant view

  - Any test that parks MUST unwind (redeem all treasury shares) — the fixture MMF and the

    `freeTreasuryBalance()` (lib/treasury) is the bigint view used for guards. Parking
    reduces both automatically because it really moves tokens out of the treasury wallet.

## 2026-07-14 08:20 - US-005 (Recall: T+0 redemption back to the settlement asset)
- `lib/treasury.ts`: `recall(positionId)` loads the position, refuses anything that is
  not ACTIVE, re-resolves the network's fund via the existing `fundAssetFor()` (so a
  position whose fund was redeployed under a different asset fails loudly rather than
  redeeming the wrong token), reads the live index, redeems the position's shares as the
  operator via `mmfOperatorWrite(network, "redeem", [treasury, shares])`, and flips the
  row to RECALLED **in place** with `recalledAt` + `txHashRecall`. The asset returned
  (principal + any yield accrued since entry) is measured as the treasury's token-balance
  delta, since a viem write only yields a receipt.
- Two new `TreasuryErrorCode`s: `POSITION_NOT_FOUND`, `POSITION_NOT_ACTIVE` — US-007 maps
  both to 404/409-style route errors.
- Audit: `TREASURY_RECALLED` with positionId, network, asset, shares, amount returned
  (decimal + base units), principal, yield, index at entry and exit, fund, tx hash. All
  base units stringified (JSON.stringify throws on bigint).
- `tests/db/treasury.test.ts` (+2 tests, 106 -> 108): a real on-chain park -> recall
  round-trip at an unchanged index returns exactly the principal — treasury token balance
  and `availableLiquidity()` both back to their pre-park values, fund balance down by the
  principal, treasury shares at 0, position RECALLED with both tx hashes, TREASURY_RECALLED
  on an INTACT audit chain; and unknown / already-recalled positions throw the typed codes
  while the history row survives untouched.
- Files changed: lib/treasury.ts, tests/db/treasury.test.ts, AGENTS.md (architecture-map
  row + append-only-positions invariant).
- Checks: 108 tests pass, `npx tsc --noEmit` clean, `npm run lint` clean.
- **Learnings for future iterations:**
  - No contract change was needed — `redeem` already existed from US-001 and `MMF_ABI` /
    `mmfOperatorWrite` from US-003/US-004, so no `npm run compile` step and no fixture
    change. US-006 (`accrue`) is in the same position: the contract and the operator path
    are already there, only lib + tests are owed.
  - Shares are stored on the row, so recall does NOT need `sharesOf` — it redeems exactly
    `BigInt(position.shares)`. That is what keeps multiple concurrent positions on the same
    treasury wallet independent (the contract only tracks an aggregate per account).
  - At an unchanged index a round-trip is exact (no floor-division dust) because
    `shares = amount * 1e18 / index` then `asset = shares * index / 1e18` inverts cleanly at
    par. After US-006 accrues the index, do NOT expect park/recall to be exact — assert
    `>= principal` instead.
  - `recall()` reads the index for the audit trail *before* redeeming; if a future story
    accrues between the read and the write, the audited `indexAtExit` could lag the actual
    payout. Fine today (single-threaded demo), worth knowing if accrual ever runs on a timer.
  - Test isolation: the file's existing `unwind()` (redeem all treasury shares + delete the
    file's position rows) is still the right ending for every new treasury test — the
    fixture fund is shared and `tests/integration/mmf.test.ts` asserts it sits at par with
    exactly MMF_YIELD_BUFFER.
